INCIDENT

매일 같은 시각, QA DB CPU가 70%까지 오르는 문제

RESOLVED
영향
QA DB 성능 저하
지속
11일간 하루 두 번 반복
역할
원인 추적 · 조치
  1. 감지

    매일 10시와 18시에 CPU가 평소 20%대에서 70%까지 오르는 패턴을 확인했습니다.
    시간이 정확히 반복된다는 점에서 예약 작업을 먼저 의심했습니다.

  2. 추적

    서버 33대의 크론, DB 이벤트 스케줄러, 애플리케이션 스케줄러를 차례로 확인하며 후보를 하나씩 지웠습니다.

  3. 원인

    마지막으로 남은 Lambda 배치를 디컴파일해, 월별 통계 약 2만 건을 지우고 다시 쓰는 로직을 찾았습니다.
    이 대량 변경이 실시간 복제로 그대로 넘어오며 부하를 만들고 있었습니다.

  4. 조치

    운영팀과 테이블 사용 여부를 확인한 뒤 해당 통계 테이블을 복제 대상에서 제외했습니다.

  5. 남긴 것

    원인 분석 기록과 복제 대상 테이블을 관리하는 기준을 문서로 남겼습니다.

결과
  • 반복 부하 원인 제거
  • 복제 대상 관리 기준 수립
INCIDENT

QA DB 커넥션이 주기적으로 급증하는 문제

RESOLVED
영향
DB 커넥션 15개 → 84개
특이점
운영은 문제없음
역할
원인 분석 · 안전 제거
  1. 감지

    QA DB 커넥션 수가 일정한 주기로 15개에서 84개까지 늘어나는 현상을 확인했습니다.

  2. 추적

    커넥션을 만드는 프로세스를 따라가, 오래전부터 기동에 실패한 채 남아 있던 웹앱을 찾았습니다.

  3. 원인

    기동 실패 직전에 만들어진 DB 풀의 정리 스레드가 살아남아 30초마다 커넥션을 열고 버리고 있었습니다.
    운영은 실패 지점이 달라서 우연히 안전했을 뿐, 같은 위험을 안고 있었습니다.

  4. 조치

    언제든 되돌릴 수 있는 방식으로 웹앱을 제거하고, 운영 서비스는 재기동 없이 처리했습니다.

  5. 남긴 것

    환경별로 실패 지점이 다를 수 있다는 점까지 포함한 원인 분석과 레거시 앱 제거 절차를 남겼습니다.

결과
  • 커넥션 82 → 1
  • 누수 로그 하루 960건 → 0
IMPROVEMENT

이미지 저장소 디스크가 가득 차 배포가 멈춘 문제

IMPROVED
영향
빌드 · 배포 실패
원인 범위
저장소 정리 구조 전체
역할
원인 분석 · 자동화
  1. 감지

    빌드가 이미지 업로드 단계에서 실패했고, 저장소 서버 디스크가 100%인 것을 확인했습니다.

  2. 추적

    저장소 로그와 파일을 직접 확인하며 태그를 지워도 디스크가 줄지 않는 이유를 찾았습니다.

  3. 원인

    이미지 삭제가 4단계로 나뉘어 동작하는데, 마지막 정리 단계가 등록되어 있지 않았습니다.
    업로드할 때마다 남는 임시 파일도 함께 쌓이고 있었습니다.

  4. 조치

    파이프라인 마지막 단계에 최근 이미지만 남기는 정리 자동화를 넣고, 정리 작업을 순서대로 예약했습니다.
    정리가 실패해도 배포는 멈추지 않도록 안전장치를 두었습니다.

  5. 남긴 것

    이미지 태그 규칙과 저장소 정리 절차를 운영 가이드로 정리했습니다.

결과
  • 디스크 70% → 29%
  • 약 20GB 회수
